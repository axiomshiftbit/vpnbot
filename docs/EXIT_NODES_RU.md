# Узлы выхода и группы

Меню: **Xray → Узлы выхода**. Правила применяются на сервере к назначенным
пользователям Xray. Клиентскую подписку ради изменения правил обновлять не нужно.
Служебные «Профили для узла» исключены из дальнейшего перенаправления на узлы,
чтобы два сервера не образовали петлю.

## Обычный узел

1. На сервере выхода создайте **Профиль для узла**.
2. В firewall сервера выхода разрешите адрес основного сервера. В профилях nftables
   для этого предусмотрен `my_server`; иначе общие ограничения новых соединений
   могут мешать нескольким пользователям одного узла.
3. На основном сервере добавьте выданную ссылку. Поддерживаются VLESS REALITY,
   VLESS WebSocket/XHTTP с TLS и Trojan gRPC с TLS. Проверка TLS обязательна.
4. Добавьте назначения через **Маршруты** или **Наборы .srs/.mrs** и назначьте
   пользователей. **Настройки → Новым пользователям** действует на создаваемых пользователей.
5. Выберите поведение при отказе: **напрямую** или **блок**. У обычного удалённого
   узла по умолчанию разрешён прямой запасной выход; строгий режим включается явно.

Переключение при отказе относится к новым соединениям. Уже открытый TCP-сеанс
не переносится на прямой выход: приложение должно переподключиться.
Xray оценивает доступность по контрольному HTTP-запросу через узел. Блокировка
контрольного адреса может вызвать запасной выход даже при работающем сервере,
а успешная проверка не гарантирует доступность каждого сайта. Отказ и возврат
обнаруживаются с задержкой наблюдателя; это не мгновенное переключение.
На запуске до первых успешных проб также действует выбранный запасной выход.
В строгом режиме во всех этих случаях прямого выхода нет.

Поддерживаются домены, `domain:`, `full:`, `keyword:`, `regexp:`, `geosite:`,
`geoip:`, `ext:`, `extip:`, IPv4/IPv6 и CIDR. Отсутствующие наборы или `.dat` у
строгого узла закрывают доступ назначенным пользователям, пока правила не будут
восстановлены. Бот не сохраняет новые заведомо неготовые строгие правила.

**Подписка узла** принимает URL подписки «Профиля для узла». При смене ключей или
транспорта ссылка обновляется автоматически: планово раз в 6 часов и после
неудачной проверки. Скачивание ограничено публичными HTTPS-адресами; переадресации
проверяются. Проверка всех узлов выполняется партиями до четырёх одновременно.

Счётчик трафика накапливается между перезапусками Xray. В него входят проверки
узла и трафик групп, использующих этот узел. Кнопка сброса начинает новый отсчёт.

## Весь трафик одного пользователя

Откройте **Xray → Узлы выхода → нужный узел → Пользователи** и нажмите
**Весь трафик** справа от имени. Та же кнопка есть в **Узлах выхода**
карточки пользователя. У управляемой ноды список доступен из её карточки.
Отмечать домены и сети для полного выхода не требуется.

Выбор действует на новые внешние TCP- и UDP-соединения, которые клиент передал
основному Xray. Если на устройстве включена раздельная маршрутизация, для полного
туннеля выберите VPN для всех назначений также в клиенте. Внутренний DNS AdGuard
остаётся доступен. Блок-лист, запрет торрентов и настройка QUIC продолжают действовать.
В полном режиме внутренний SOCKS-сервис WARP закрыт для этого пользователя.

У пользователя один полный выход. Выбор другой ноды переключает его на неё.
У остальных пользователей этой же ноды могут оставаться обычные маршруты по спискам.
При обрыве связи или отключении полного выхода новые внешние соединения блокируются,
даже если узел разрешает прямой запасной путь для маршрутов по спискам. У группы
ручной выбор «Напрямую» также блокирует полный маршрут.

Повторное нажатие **Весь трафик** возвращает пользователя к назначенным спискам.
Чтобы снять и назначение по спискам, нажмите кнопку с именем слева. Удаление ноды
снимает её назначения. Новым пользователям автоматически назначаются только списки.

## IPv6 этого сервера

Этот тип выхода всегда строгий: назначения должны быть доступны по IPv6;
возврата на IPv4 нет. Нужны настроенные IPv6, Docker-сеть и SNAT/firewall хоста.
Само добавление узла не назначает публичный IPv6 серверу.

Пока используется локальный IPv6-выход, обычный прямой выход сохраняет IPv4.
Когда больше нет таких назначений и отключена выделенная IPv6-сеть бота,
бот снимает собственное ограничение IPv4. Пока сеть явно включена на хосте,
обычный выход остаётся IPv4. Ручные настройки прямого выхода сохраняются. Старое ядро
26.7.28 и современные версии получают совместимые варианты настроек.

Сертификат удостоверяет доменное имя. Для того же домена отдельный сертификат
на IPv6-адрес не нужен. Исходящий IPv6-выход вообще не требует сертификата сервера.

## Навигация и приоритет

В **Xray → Узлы выхода** выберите **Добавить выход**: удалённый сервер,
группу или локальный IPv6. Для приёма трафика другого бота используйте
**Принимать трафик других ботов** — это прежний «Профиль для узла».

Карточка показывает состояние и ведёт к маршрутам, наборам и пользователям.
В **Настройках** находятся имя, QUIC, назначение новым пользователям, режим
отказа, ссылка и подписка, удаление. **Диагностика** содержит историю,
измерение скорости, обновление наборов и сброс счётчика с подтверждением.
Справка возвращает в тот экран, из которого её открыли.

**Приоритет маршрутов** позволяет перемещать выходы стрелками ↑/↓.
При пересечении правил одного пользователя побеждает первый подходящий выход.
Блок-лист и защитные правила остаются выше. Имена и состав групп, маршруты,
пользователи и накопленный трафик при перемещении сохраняются. Эта операция
может перезапустить Xray: изменяется и порядок служебных входов проверки.
Кнопки старого порядка отклоняются — откройте меню заново.

Цвет в списке отражает последнюю проверку. В карточке показана её дата;
результат старше 15 минут отмечен как устаревший. Это не постоянный монитор
каждого соединения. Отключение узла снимает его маршруты по спискам. Пользователи с полным выходом через этот узел остаются без внешнего доступа до его включения или смены назначения.

**При отказе** открывает явный выбор политики. Разрешение прямого выхода
может раскрыть адрес этого сервера назначениям, которые обычно идут через узел,
в том числе до первых успешных проб после запуска. Локальный IPv6 всегда строгий.
Старый переключатель теперь открывает этот выбор без изменения настройки.

**Проверить обновление ссылки** в настройках удалённого узла скачивает его
подписку сейчас. Ошибка сохраняет прежнюю рабочую ссылку. **Обновить наборы**
в диагностике обновляет только `.srs/.mrs` и проверяет доступность узла.

При импорте `.srs` суффикс `.example.org` охватывает только поддомены,
а `example.org` включает и сам домен. В `.mrs` запись `+.example.org`
включает сам домен и его поддомены, `.example.org` выбирает только
поддомены, а `*.example.org` выбирает один уровень. **Обновить наборы**
перечитывает исходный файл. В именованном списке сохраняются развёрнутые
правила. Для изменения ранее импортированных правил повторите импорт и
примените черновик ноды.

## Группа узлов

1. Добавьте обычные удалённые узлы и включите их.
2. Нажмите **Добавить выход → Группа узлов → Состав и выбор узла**.
   Левая кнопка добавляет/убирает участника, правая выбирает его вручную.
3. Добавьте маршруты и пользователей самой группе. Назначать этим пользователям
   те же отдельные узлы необязательно: у них собственные независимые правила.
4. Оставьте автоматический выбор или выберите участника вручную.

Автоматический режим `leastPing` выбирает живого участника с минимальной
измеренной задержкой. Это измерение до контрольного HTTP-адреса, а не гарантия
максимальной скорости YouTube. После запуска нужно дождаться первых проб.

Группа создаётся с блокировкой при отказе всех участников. Разрешить прямой
запасной выход можно отдельно. Ручная кнопка **Напрямую** появляется только при
таком разрешении. В ручном режиме отказ, отключение или удаление выбранного
участника блокируют маршрут; автоматическая замена не включается сама.

В группы включаются обычные удалённые узлы. Вложенные группы и локальный IPv6
не участвуют в балансировке. Общий предел — 8 записей, включая группы.
Проверка автоматической группы проверяет участников без прямого запасного
выхода: успешный прямой доступ не маскирует отказ группы.

Правила обрабатываются в порядке узлов. При пересечении назначений одного
пользователя сработает первое подходящее правило. Блок-лист и защитные правила
имеют приоритет над узлами и группами.

## Применение без перезапуска

Бот автоматически использует API Xray, когда проверено соответствие работающего
процесса сохранённому конфигу и изменение поддерживается:

- изменение правил и балансировщиков при неизменных DNS, политике и observatory;
- ручной выбор участника группы;
- добавление пользователей VLESS, VMess и Trojan без изменения существующих;
- добавление выходов без изменения или удаления существующих.

Существующие TCP-соединения сохраняются; новые правила действуют на новые
соединения. Отзыв пользователя, замена его ключей, изменение/удаление выхода,
смена транспорта, ядра, DNS, наблюдателя или политики требуют полного
перезапуска. Изменение состава группы также может потребовать перезапуска.

Для 26.7.28 используется полный перезапуск: его замена правил через API не
атомарна. Для 26.9.30, 26.10.29, 26.10.31 и форков 26.10.28-1202, 26.11.1-1424 и 26.11.10-1249 проверено горячее применение.
Старый образ без Python или без нового помощника продолжает работать через
полный перезапуск. API слушает только `127.0.0.1:8080` внутри `xr`; публиковать
этот порт нельзя.

При ошибке API бот выполняет полный перезапуск с предварительно проверенной
конфигурацией. Уже существующие выходы горячая операция никогда не удаляет:
соединение, которое выбрало маршрут до смены правил, не должно попасть в прямой
выход из-за исчезнувшего обработчика. Служебное состояние хранится в `/run`
внутри `xr`, привязано к PID, времени старта и контрольной сумме конфигурации.
Ключи передаются помощнику через SSH stdin и временный закрытый каталог;
в аргументы процессов и общие журналы они не записываются.

Ручные изменения работающего Xray через API вне бота не поддерживаются:
после них выполните полный перезапуск ядра, чтобы файл и процесс совпадали.

## Доступ к AdGuard

Для входа в панель основного AdGuard откройте мини-приложение Telegram или получите в боте одноразовую ссылку для браузера. Пропуск действует 15 минут с момента авторизации в Telegram или выдачи ссылки. Переход по ссылке и действия в панели не продлевают срок. После истечения срока потребуется новый вход.

Кнопка «Закрыть доступ к панели» немедленно отзывает действующие пропуска и неиспользованные ссылки. Фильтрация DNS продолжает работать. Кнопка «Открыть доступ к панели» разрешает новый вход. Выключение режима стороннего браузера отзывает его пропуска. Смена пароля через бот завершает предыдущие сеансы панели.

## Связь между ботами по IPv6

Настройка «Связь с узлом: IPv6» в профиле принимающего узла независима от
«Выход: только IPv6». Для полной цепочки включите обе и задайте строгую политику
на основном боте. Требования Reality, firewall и команды подготовки описаны
в [IPV6_NODE_RU.md](IPV6_NODE_RU.md).
