# Защита контейнеров и автоматическое окно SSL

Установка рассчитана на один VPN-бот на Linux-хосте с systemd и Docker bridge.
Запускайте команды от root из каталога бота (обычно `/root/vpnbot`). Python —
системный `python3`; виртуальное окружение `/root/skripts` для этих служб не нужно.
Секреты, домены и публичные адреса в исходный код добавлять не требуется.

## Подготовка сервера

1. Подготовьте Debian/Ubuntu и восстановите `/opt` из VeraCrypt.
2. Выберите основной профиль nftables, укажите его собственный WAN, публичные
   адреса и доверенные сети. Проверьте и установите `/etc/nftables.conf` по
   инструкции комплекта `/opt/nftables`. Автоматизация бота не заменяет этот файл
   готовым профилем: добавляется только include отдельной защиты контейнеров.
3. Установите бот штатным установщиком. Он устанавливает `nftables`, `iproute2`
   и `util-linux`. При запуске Compose сначала устанавливается защита мостов,
   после запуска контейнеров — окно ACME, если основной firewall содержит
   `ip filter acme_http_fwd`.
4. Настройте в боте домен и Let's Encrypt. Для HTTP-01 все A-записи используемых
   имён должны вести на публичный IPv4 этого сервера. Установщик отказывает при
   наличии AAAA: это окно работает по IPv4. Исходящий IPv6 у узлов не требует AAAA
   и не меняет данный порядок.

Если подходящего ACME-набора нет, выводится предупреждение и установка окна
пропускается. Если служба уже была установлена, а набор исчез, это ошибка.
Несоответствие правил, прав файлов или DNS останавливает настройку с ошибкой;
защита не отключается для обхода проверки.

## Как определяется сервер

`container_origin_guard.py` читает из локального Docker только метаданные:
Compose labels, PID, имена сетей, адреса и MAC. Через сетевые пространства
контейнеров он сопоставляет их с хостовыми veth-портами. Полное окружение
контейнеров не выгружается. Для маршрутизируемых клиентов выбираются только
несекретные поля подсетей WG/OpenVPN/IPsec; OpenConnect использует штатную подсеть.

`setup_acme.py` получает WAN, публичный IPv4 и HTTP upstream из действующих
правил nftables и сверяет их с постоянным файлом, загруженным в отдельном netns.
Проверяет, что адрес назначен WAN, DNAT ведёт в nginx этого бота, а монтирования
ACME имеют нужные права. Список доменов берётся через проверочный интерфейс бота.
Создаётся только цель `vpnbot`; существующие дополнительные цели, `auto=false`,
история обновлений и настройки сохраняются. Повторный `ensure` не переустанавливает
актуальные службы и не закрывает окно текущего выпуска.

## Ручная установка и диагностика

```bash
cd /root/vpnbot
python3 scripts/host_services.py prepare --bot-dir /root/vpnbot
python3 scripts/host_services.py finalize --bot-dir /root/vpnbot

# Проверить происхождение контейнеров или принудительно сверить новые veth:
python3 /usr/local/sbin/vpnbot-origin check --bot-dir /root/vpnbot
python3 /usr/local/sbin/vpnbot-origin sync
systemctl status vpnbot-origin.service vpnbot-origin-boot.service
journalctl -u vpnbot-origin.service --since '1 hour ago'
nft list table bridge vpnbot_origin

# Предварительная проверка окна; конфигурация и правила не меняются:
python3 scripts/setup_acme.py check --bot-dir /root/vpnbot --wait-lock 30
# Установить или обновить только при необходимости:
python3 scripts/setup_acme.py ensure --bot-dir /root/vpnbot --wait-lock 30
# Полная переустановка с тестовым HTTP-01 до включения таймера:
python3 scripts/setup_acme.py install --bot-dir /root/vpnbot --dry-run --wait-lock 30
# Отдельный тест уже установленного агента:
python3 scripts/setup_acme.py test --bot-dir /root/vpnbot --wait-lock 30
systemctl status acme-window.timer acme-window.path
acme-window status
journalctl -u acme-window -u acme-window-close
nft list set ip filter acme_http_fwd
```

Доступные параметры `setup_acme.py`: действие `check`, `ensure`, `install` или
`test`; `--bot-dir` (по умолчанию `/root/vpnbot`); `--nft-config` (по умолчанию
`/etc/nftables.conf`); `--profile auto|dnat|redirect` (по умолчанию автоопределение
по наличию redirect-набора); `--wait-lock 0..120` секунд (по умолчанию 0);
`--dry-run` только для `install`. DNS проверяется без печати доменов.

Параметры `container_origin_guard.py`: `install`, `check`, `sync`, `watch`, `boot`;
`--bot-dir` (по умолчанию текущий каталог), `--nft-config` (по умолчанию
`/etc/nftables.conf`, при установке). `watch` и `boot` обычно запускает systemd.
Не запускайте `boot` вручную на работающем сервере: он закрывает доступ до
следующей сверки watcher. `host_services.py` поддерживает `prepare`, `finalize`
и `--bot-dir` (по умолчанию текущий каталог).

Исходники и все каталоги пути должны принадлежать root и не быть доступны на
запись группе/остальным. Не исправляйте это рекурсивным `chmod` всего бота:
его рабочим каталогам нужны собственные права. Исправляйте только названные
проверкой объекты. Симлинки и переопределения systemd требуют ручного разбора.

## Что защищается

Таблица `bridge vpnbot_origin` проверяет кадры до conntrack и обучения FDB.
Источник привязан одновременно к мосту, хостовому ifindex, имени veth, MAC и
разрешённым адресам. Фальшивые IPv4/IPv6, ARP и объявления соседей от чужого
порта не получают доверие PHP/service. У маршрутизирующих VPN-контейнеров
разрешены их клиентские подсети. Неизвестные порты защищённых мостов закрыты,
включая вручную присоединённые контейнеры. Хост и его Docker daemon считаются
доверенными; root хоста способен изменять эту защиту.

При пересоздании контейнера новое разрешение появляется после сверки Docker
(события плюс опрос каждые 2 секунды). Возможна краткая задержка связи. Сбой
watcher сохраняет действующие ограничения, но новые контейнеры будут закрыты.
Служба автоматически перезапускается. При загрузке системы разрешения пусты,
Docker зависит от запуска закрытой базовой политики. Постоянный include и
атомарный снимок `/run/vpnbot-origin/active.nft` сохраняют защиту при штатном
полном применении nftables. Не удаляйте include из основного профиля.

Службы не делают недоверенными доверенные приложения: компрометация самого
PHP/service или Docker daemon остаётся отдельным риском. Защита происхождения
не заменяет ACL портов, проверку авторизации, обновления и ограничения нагрузки.
Нестандартные сети, привилегированные контейнеры, несколько копий одной роли,
произвольные изменения VPN-подсетей требуют проверки совместимости.

Для журналирования блокировок обновите установщик `/opt/nftables/logging` и
запустите профильный скрипт после включения guard. `BR-ORIGIN-DROP:` попадает
в `security.log`; действие определяется по действующей таблице. Если логирование
настроено до появления таблицы, повторная установка обновит таблицу действий.
Без этого `UNKNOWN` означает отсутствие подтверждённого действия в снимке,
а не отсутствие фильтрации. Журнал ограничен 5 сообщениями/с, счётчик считает
все отброшенные пакеты.

## Обновление, откат и тестовые стенды

Обновление через штатный Compose-путь повторяет проверку и обновляет копии
служб. Основной файл firewall сохраняется. Установка guard при ошибке восстанавливает
свои прежние файлы, таблицу и watcher; первоначальный основной конфиг сохраняется
в `/etc/nftables.conf.before-vpnbot-origin`. ACME хранит резервные копии установки
в `/var/backups/acme-window-setup/` с `manifest.json`. Эти копии не содержат
приватные TLS-ключи. При сообщении об ошибке отката сначала проверьте закрытие
окна и состояние служб. Не применяйте полный старый firewall вслепую.

`VPNBOT_HOST_SERVICES=off` отключает автоматические prepare/finalize в текущем
процессе — для изолированных CI-стендов с намеренно присоединёнными тестовыми
клиентами. Это не команда удаления уже установленной защиты. На обычном сервере
оставьте значение по умолчанию `on`. Опечатка в значении вызывает ошибку.
Тестовый процесс должен задавать этот параметр сам; он не берётся из настроек
бота, доступных контейнерам. В окружении без root/systemd автоматизация также
пропускается с явным сообщением.
